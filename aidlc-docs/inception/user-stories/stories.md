# User Stories

## ストーリーマップ（User Journey順）

```
初回セットアップ → テキスト入力 → 校正実行 → 結果確認・コピー → エラー対応
    US-1            US-2          US-3         US-4, US-5       US-6
```

---

## US-1: 初回セットアップ（LLMプロバイダー設定）

**As a** アプリの新規ユーザー（田中・鈴木）,
**I want to** 初回起動時にLLMプロバイダーの接続設定を行いたい,
**So that** すぐに校正機能を利用開始できる。

### Acceptance Criteria

**Scenario 1: LM Studio の設定**
- Given: アプリを起動し、設定画面を開いた状態
- When: LLMプロバイダーとして「LM Studio」を選択し、エンドポイントURLとモデル名を入力する
- Then: 設定が保存され、LM Studio APIが校正に使用される状態になる

**Scenario 2: Gemini API の設定**
- Given: アプリを起動し、設定画面を開いた状態
- When: LLMプロバイダーとして「Gemini」を選択し、APIキーとモデル名を入力する
- Then: 設定が保存され、Gemini APIが校正に使用される状態になる

**Scenario 3: プロバイダーの切り替え**
- Given: LM Studioが設定済みの状態
- When: 設定画面でプロバイダーをGeminiに切り替え、必要な情報を入力する
- Then: プロバイダーが切り替わり、次回の校正からGemini APIが使用される

### Personas
- 田中 健太: Gemini APIを主に使用（簡単なセットアップを期待）
- 鈴木 美咲: LM Studioを主に使用（用途に応じて切り替え）

---

## US-2: テキスト入力

**As a** テキストを校正したいユーザー（田中・鈴木）,
**I want to** macOSディクテーションまたは手動入力でテキストを入力したい,
**So that** 校正対象のテキストを素早く準備できる。

### Acceptance Criteria

**Scenario 1: macOS ディクテーションによる入力**
- Given: アプリの左パネル（テキストエリア）にフォーカスがある状態
- When: macOSのディクテーション機能（キーボードショートカット）で音声入力する
- Then: ディクテーション結果が左パネルにテキストとして表示される

**Scenario 2: 手動でのテキスト入力**
- Given: アプリの左パネル（テキストエリア）にフォーカスがある状態
- When: キーボードでテキストを直接入力する
- Then: 入力したテキストが左パネルに表示される

**Scenario 3: 入力テキストの編集**
- Given: 左パネルにテキストが入力されている状態
- When: テキストの一部を選択して修正する
- Then: 修正が左パネルに反映される

### Personas
- 田中 健太: 主にディクテーション入力を使用
- 鈴木 美咲: ディクテーションと手動入力を併用

## US-3: LLMによるテキスト校正

**As a** ディクテーションで入力したテキストに誤字脱字があるユーザー（田中・鈴木）,
**I want to** ボタン一つでLLMにテキストの校正を依頼したい,
**So that** 誤字脱字が修正された正確なテキストを得られる。

### Acceptance Criteria

**Scenario 1: 校正の実行**
- Given: 左パネルにテキストが入力されており、LLMプロバイダーが設定済みの状態
- When: 「校正」ボタンを押下する
- Then: テキストがLLMに送信され、校正結果が右パネルに表示される

**Scenario 2: 校正中のローディング表示**
- Given: 校正ボタンを押下した状態
- When: LLMが校正処理中である
- Then: ローディングインジケーターが表示され、処理中であることがわかる

**Scenario 3: 日本語テキストの校正**
- Given: 左パネルに日本語テキストが入力されている状態
- When: 校正を実行する
- Then: 日本語の誤字脱字が修正されたテキストが右パネルに表示される

**Scenario 4: 英語テキストの校正**
- Given: 左パネルに英語テキストが入力されている状態
- When: 校正を実行する
- Then: 英語のスペルミスや文法エラーが修正されたテキストが右パネルに表示される

### Personas
- 田中 健太: 日本語の会議メモ・報告書の校正
- 鈴木 美咲: 日本語・英語混在の技術ドキュメントの校正

---

## US-4: 校正結果の確認・編集

**As a** 校正結果を確認したいユーザー（田中・鈴木）,
**I want to** 校正後のテキストを確認し、必要に応じて手動で編集したい,
**So that** 最終的なテキストの品質を自分でコントロールできる。

### Acceptance Criteria

**Scenario 1: 校正結果の確認**
- Given: LLMによる校正が完了した状態
- When: 右パネルを確認する
- Then: 校正後のテキストが右パネルに表示されている

**Scenario 2: 校正結果の手動編集**
- Given: 右パネルに校正結果が表示されている状態
- When: 校正結果の一部を選択して修正する
- Then: 修正が右パネルに反映される

### Personas
- 田中 健太: 校正結果をそのまま使用することが多い
- 鈴木 美咲: 技術用語の校正結果を確認・修正する

---

## US-5: 校正結果のコピー

**As a** 校正済みテキストを他のアプリで使いたいユーザー（田中・鈴木）,
**I want to** 校正結果をワンクリックでクリップボードにコピーしたい,
**So that** メールやドキュメントにすぐ貼り付けられる。

### Acceptance Criteria

**Scenario 1: コピーボタンによるクリップボードコピー**
- Given: 右パネルに校正済みテキストが表示されている状態
- When: 「コピー」ボタンを押下する
- Then: 右パネルのテキスト全体がクリップボードにコピーされる

**Scenario 2: コピー完了のフィードバック**
- Given: コピーボタンを押下した状態
- When: クリップボードへのコピーが完了する
- Then: コピー完了を示す視覚的フィードバック（ボタンの色変化等）が表示される

### Personas
- 田中 健太: 校正後すぐにメールやSlackに貼り付け
- 鈴木 美咲: 校正後にドキュメントやコードコメントに貼り付け

---

## US-6: エラー発生時の対応

**As a** アプリを使用中のユーザー（田中・鈴木）,
**I want to** エラーが発生した場合に原因と対処法がわかるメッセージを見たい,
**So that** 問題を自分で解決して作業を続けられる。

### Acceptance Criteria

**Scenario 1: API接続エラー**
- Given: LLMプロバイダーが設定済みだがAPIサーバーに接続できない状態
- When: 校正ボタンを押下する
- Then: 「APIサーバーに接続できません。接続先URLと接続状態を確認してください」等のエラーメッセージが表示される

**Scenario 2: 設定不備エラー**
- Given: LLMプロバイダーの設定が未完了または不正な状態
- When: 校正ボタンを押下する
- Then: 「LLMプロバイダーの設定を確認してください」等のエラーメッセージが表示され、設定画面への誘導がある

**Scenario 3: 空テキスト送信**
- Given: 左パネルが空の状態
- When: 校正ボタンを押下する
- Then: 「校正するテキストを入力してください」等のメッセージが表示され、APIは呼び出されない

### Personas
- 田中 健太: わかりやすいエラーメッセージで自己解決できることを期待
- 鈴木 美咲: 技術的な詳細（HTTPステータスコード等）も確認できると助かる
